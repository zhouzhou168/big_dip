# big_dip

用日收盘跟踪 7 个标的的当前回撤，以及从各自序列起点至今的历史最大回撤。克隆之后可以直接重新抓数、重新计算，仓库里不存放行情缓存。

**这不是投资建议，也不构成任何买卖依据。** 行情接口会延迟、修订或中断，算出的回撤只描述过去的收盘价路径。

## 安装

需要 Python 3.11 或更新版本。运行本身不用第三方包。

```bash
python -m venv .venv
source .venv/bin/activate
pip install -e .
```

也可以不安装，直接：

```bash
PYTHONPATH=src python -m big_dip
```

## 运行

```bash
python -m big_dip -o out/drawdown.json
```

终端会打印一张表，同时把完整结果写到 `out/drawdown.json`。只算其中几个标的：

```bash
python -m big_dip --assets sse,btc
```

可选的 key：`sse`、`szse`、`cyb`、`ixic`、`gspc`、`btc`、`eth`。

短时间反复调试时，可以把原始响应放进缓存目录，避免反复打接口。缓存不要提交进 git：

```bash
python -m big_dip --cache-dir .cache
```

默认每次都重新下载。

## 标的和序列起点

| 名称 | 代码 | 序列从哪里开始 |
|---|---|---|
| 上证指数 | 000001.SH | 1990-12-19（官方可回溯的基日；指数发布日是 1991-07-15） |
| 深证成指 | 399001.SZ | 1994-07-20 官方基期。更早的点位即使源里有，也不参与计算 |
| 创业板指 | 399006.SZ | 2010-06-01 |
| 纳斯达克综合指数 | ^IXIC | 1971-02-05，基点 100。这是综合指数，不是纳斯达克 100 |
| 标普 500 | ^GSPC | 尽量从 1927-12-30 附近的历史综合指数开始：1950 年起用腾讯日线，更早用 Yahoo 补齐。另外单独给出 1957-03-04 起的现代序列 |
| BTC | BTC-USD | CoinMetrics 最早可靠成交日价，约 2010-07-18。不是 2009 年创世块 |
| ETH | ETH-USD | 主网上线后的最早可靠日价，约 2015-08-08 |

实际用到的第一根、最后一根收盘，以当次 JSON 里的 `first_date` / `last_date` 为准。

## 数据源

程序里写死的是下面这些公开接口，不需要密钥。

- **A 股指数**：新浪财经日 K，`https://finance.sina.com.cn/realstock/company/{symbol}/hisdata/klc_kl.js`。三个代码分别是 `sh000001`、`sz399001`、`sz399006`。响应是一段压缩比特流，程序在本地解出日期和收盘，只用收盘。深证成指会丢掉 1994-07-20 之前的记录。
- **标普 500**：1950 年起用腾讯证券 `us.INX` 的日 K 收盘（不复权）。1950 年之前优先用 Yahoo Finance `^GSPC` 的 `close`，按大约 5 年一段下载。Yahoo 被限流时，改用一份公开转存的 Yahoo 日线 `https://datayyy.com/data_csv/sp500daily.csv`，只取腾讯起点之前的日期。衔接日两边的收盘写在 `source.splice`，价格不缩放。两处都失败时，序列从腾讯的第一天起算，JSON 会说明其中没有 1929–1932 年。
- **纳斯达克综合指数**：Nasdaq 官网 `COMP` 历史日收盘，`https://api.nasdaq.com/api/quote/COMP/historical`。这是综合指数，不是纳斯达克 100。官网序列目前从 1984 年附近开始，更早的交易日用圣路易斯联储 FRED `NASDAQCOM`（`https://fred.stlouisfed.org/series/NASDAQCOM`）补到 1971-02-05。FRED 的 CSV 在 TLS 1.3 下经常没有正文，程序固定用 TLS 1.2。FRED 失败时再试 Yahoo `^IXIC`。衔接日同样只记录价差，不缩放。官网历史里偶尔有假期日期，样本根数可能比另一家日历略多，回撤仍按这些收盘计算。
- **BTC、ETH**：CoinMetrics Community API 的日频 `PriceUSD`，`https://community-api.coinmetrics.io/v4/timeseries/asset-metrics`。这是一套参考价格，不是某一家交易所的官方收盘；和交易所日 K 相比，同一天常常差零点几个百分点。整段历史只用这一套价格，避免把两个水平不一样的序列接在一起，人为造出跳空。

美股、A 股如果在收盘前运行，当天未完成的 K 线不会算进去。加密货币只保留已经结束的 UTC 日。美股遇到提前收盘的半天市时，当天收盘要等到美东 16:00 之后才会被算作“已完成”。

## 计算口径

- 只用日收盘。不含红利再投资，也不用盘中最高、最低。例如上证 2007-10-16 常被提到的 6124 是盘中高点，本项目只看那天的收盘。
- 某一天的回撤 = 当天收盘 / 截至当天的滚动最高收盘 − 1。历史最大回撤是这段序列里最负的回撤。
- 峰值日期是谷值之前，滚动最高收盘最后一次被打平或刷新的那一天。收盘高点日期则是窗口内最高收盘第一次出现的日子。
- 收复日是谷值之后，收盘第一次大于或等于该次峰值的日期。到最新收盘还没回去，就记为未收复。
- 窗口有四档：成立以来、今年以来、近 1 年、近 5 年。后三档只在窗口内部滚动，不把窗口开始前的高点带进来。近 1 年、近 5 年以最新收盘日为终点，向前推 1 个或 5 个日历年；起点当天若不是交易日，就从其后的第一根收盘算起。
- 标普 500 额外有 `modern1957`：从 1957-03-04 算到最新收盘，和“成立以来”并存，不替换它。
- 时间标注用 Asia/Shanghai（UTC+8）。

不同供应商的早期日线可能差几天或差几个最小报价单位，回撤比例会有细小差别。JSON 里的数字是当次下载重新算出来的，不是写死的对照答案。

## 输出

终端表格里的价格和百分比做了四舍五入，方便阅读。`out/drawdown.json` 保留计算用的浮点数。每个标的大致是：

- `source`：这次实际用的接口、字段，以及参与计算的行数
- `windows.inception`：成立以来，主结果
- `windows.ytd` / `y1` / `y5`：今年以来、近 1 年、近 5 年
- `windows.modern1957`：只有标普 500 有

每个窗口包含最新收盘和日期、收盘高点及日期、当前回撤 `current_dd`、最大回撤 `mdd`、峰值和谷值的日期与点位、是否收复及收复日。回撤是负数，例如 `-0.20` 表示下跌 20%。

某一个标的抓取失败时，其余标的仍会写入 JSON，失败原因在 `errors` 里，进程以退出码 1 结束。
